{{- /* SITE FORK of themes/ryder/layouts/_default/list.html. Identical to the theme template except for the card lookup in the grid below. Diff it against the submodule on every Ryder bump — see CLAUDE.md > "Forked theme partials". Why it exists: the theme reads `listCardType` once, outside the range, and renders every page in the grid with it. That is a container-level setting — "what card does this grid use" — so a page's own `cardType` was never consulted on a section list. The home feed does not have this problem, because layouts/_default/home.html already resolves the card per page through utils/card-type.html. The result was one feed disagreeing with another about the same page: a post carrying `cardType = "-image"` drew its lead image on the home page and a plain category-colour card on /posts/. The fix is to call the same helper the home feed calls, inside the range, with the container's `listCardType` passed in as the fallback. That keeps the container setting authoritative for pages that express no preference — a section can still put every card in one style — while letting an individual page opt into its own. utils/card-type.html also carries the `Kind == "page"` guard that stops a section's own `_index.md` from drawing an item card when a [cascade] puts `cardType` on it. This is a candidate for upstreaming, along with the helper it calls; doing so retires this fork. */ -}} {{- define "main" -}}
